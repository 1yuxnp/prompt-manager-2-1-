# 나만의 프롬프트 관리 프로그램

Python을 활용하여 자주 사용하는 프롬프트를 관리할 수 있는 콘솔 프로그램입니다.

프롬프트를 카테고리별로 조회하고 키워드로 검색할 수 있으며, 자주 사용하는 프롬프트를 즐겨찾기로 관리할 수 있도록 구현했습니다.

---

## 개발 환경

- Python 3.14.7
- Visual Studio Code
- Git 2.55.0
- GitHub
- Windows

### 버전 확인

```bash
python --version
git --version
```

실행 결과:

```text
Python 3.14.7
git version 2.55.0.windows.4
```

Git 사용자 정보도 초기 설정을 통해 등록했습니다.

## 실행 방법

### 1. 저장소 Clone

```bash
git clone https://github.com/1yuxnp/prompt-manager-2-1-.git
```

### 2. 프로젝트 폴더 이동

```bash
cd prompt-manager-2-1-
```

### 3. 프로그램 실행

```bash
python main.py
```

프로그램 실행 후 메뉴 번호를 입력하여 원하는 기능을 사용할 수 있습니다.

---

## 주요 기능

### 1. 프롬프트 추가

새로운 프롬프트의 제목, 내용, 카테고리를 입력하여 저장할 수 있습니다.

제목과 내용이 비어 있는 경우 다시 입력하도록 처리했습니다.

### 2. 프롬프트 목록

저장된 모든 프롬프트를 번호와 함께 확인할 수 있습니다.

각 프롬프트의 제목, 카테고리, 즐겨찾기 여부를 확인할 수 있습니다.

### 3. 카테고리별 조회

카테고리를 선택하면 해당 카테고리에 등록된 프롬프트만 확인할 수 있습니다.

### 4. 프롬프트 검색

검색어를 입력하여 프롬프트의 제목 또는 내용에 포함된 키워드를 검색합니다.

검색은 대소문자를 구분하지 않으며 부분 문자열을 기준으로 검색합니다.

예를 들어 `블로그`를 검색하면 제목이나 내용에 `블로그`가 포함된 프롬프트가 검색됩니다.

### 5. 프롬프트 상세 보기

프롬프트 번호를 선택하여 제목, 내용, 카테고리, 즐겨찾기 여부 등 상세 정보를 확인할 수 있습니다.

### 6. 즐겨찾기 관리

프롬프트 번호를 입력하여 즐겨찾기를 추가하거나 해제할 수 있습니다.

### 7. 즐겨찾기 목록

즐겨찾기로 설정된 프롬프트만 모아서 확인할 수 있습니다.

### 8. 잘못된 입력 처리

메뉴에서 잘못된 번호를 입력하면 안내 메시지를 출력하고 다시 메뉴를 선택할 수 있도록 구현했습니다.

---

## 프롬프트 카테고리

프로그램에서는 다음과 같은 카테고리를 사용합니다.

- 텍스트 생성
- 이미지 생성
- 영상 생성
- 페르소나
- 자동화
- 기타

카테고리는 미리 정의된 목록을 기준으로 선택하도록 구성했습니다.

현재 프로젝트의 필수 범위에서는 카테고리 자체를 생성하거나 삭제하는 기능은 구현하지 않았습니다.

---

## 기본 등록 프롬프트

프로그램 시작 시 이전 미션에서 작성한 프롬프트가 기본 데이터로 등록되어 있습니다.

예시:

- Term Cafe UI 생성
- COOL SPOT 광고 이미지
- ExamPilot 학습 계획

프로그램 실행 중 새로 추가하거나 변경한 데이터는 프로그램 종료 시 초기화됩니다.

이는 이번 프로젝트의 필수 요구사항에 맞춘 설계입니다.

---

## 데이터 구조

프롬프트 데이터는 `리스트(List)`와 `딕셔너리(Dictionary)`를 사용하여 관리합니다.

각 프롬프트는 하나의 딕셔너리로 표현하고, 여러 프롬프트를 리스트에 저장합니다.

각 프롬프트는 다음 정보를 포함합니다.

- 제목
- 내용
- 카테고리
- 즐겨찾기 여부

예시:

```python
prompts = [
    {
        "title": "Term Cafe UI 생성",
        "content": "카페 음료 주문 앱 UI를 생성해주세요.",
        "category": "이미지 생성",
        "favorite": False
    }
]
```

### 리스트와 딕셔너리를 사용한 이유

리스트는 여러 개의 프롬프트를 순서대로 저장하고 번호를 이용해 접근하기 쉽다는 장점이 있습니다.

딕셔너리는 하나의 프롬프트에 여러 속성을 `key-value` 형태로 저장할 수 있어 제목, 내용, 카테고리, 즐겨찾기 상태를 관리하기 편리합니다.

반면 데이터가 많아지면 리스트를 순차적으로 검색해야 하기 때문에 검색 효율이 떨어질 수 있습니다.

향후 데이터가 많아질 경우 JSON 파일이나 데이터베이스를 사용하는 방식으로 확장할 수 있습니다.

---

## 입력 검증

사용자가 잘못된 값을 입력했을 때 프로그램이 종료되지 않도록 입력값을 확인합니다.

주요 검증 내용은 다음과 같습니다.

- 빈 문자열 입력 확인
- 메뉴 번호 범위 확인
- 카테고리 선택 범위 확인
- 존재하지 않는 프롬프트 번호 확인
- 숫자가 필요한 위치에 잘못된 문자 입력 확인

잘못된 입력이 들어오면 안내 메시지를 출력하고 다시 입력할 수 있도록 처리했습니다.

---

## 프로그램 반복 구조

프로그램은 `while True` 반복문을 사용하여 메뉴를 계속 출력합니다.

사용자가 하나의 기능을 실행한 후 다시 메뉴로 돌아갈 수 있도록 하기 위해 반복 구조를 사용했습니다.

사용자가 `0. 종료`를 선택하면 `break`를 사용하여 반복문을 종료하고 프로그램을 종료합니다.

---

## 검색 방식과 한계

현재 검색은 제목과 내용에 대해 부분 문자열을 확인하는 방식으로 구현했습니다.

대소문자를 구분하지 않도록 `lower()`를 사용하여 검색합니다.

현재 방식은 구현이 간단하고 작은 데이터에서 사용하기 쉽다는 장점이 있습니다.

하지만 데이터가 매우 많아질 경우 모든 프롬프트를 순차적으로 확인해야 하므로 검색 속도가 느려질 수 있습니다.

향후에는 정규식, 토큰화 또는 데이터베이스 검색 등을 적용하여 검색 기능을 확장할 수 있습니다.

---

## 영속화 설계

현재 필수 구현 범위에서는 프로그램 실행 중에만 데이터를 유지하고 프로그램 종료 시 초기화하도록 구현했습니다.

향후 프롬프트 데이터를 영구적으로 저장해야 한다면 JSON 파일을 사용하는 방식을 우선적으로 고려할 수 있습니다.

예를 들어 다음과 같은 구조로 저장할 수 있습니다.

```text
prompts.json
```

JSON을 사용하는 이유는 Python의 리스트와 딕셔너리 구조를 그대로 저장하고 다시 불러오기 쉽기 때문입니다.

향후 구현한다면 프로그램 시작 시 JSON 파일을 불러오고, 프롬프트 추가·수정·삭제 또는 즐겨찾기 변경 시 JSON 파일을 다시 저장하는 방식으로 구현할 수 있습니다.

데이터 규모가 커지면 SQLite와 같은 데이터베이스를 사용하는 방법도 고려할 수 있습니다.

## 중복 및 충돌 처리 규칙

현재 프롬프트는 번호를 기준으로 구분하여 관리합니다.

따라서 같은 제목의 프롬프트를 추가하더라도 기존 프롬프트를 덮어쓰지 않고 별도의 항목으로 저장합니다.

카테고리는 미리 정의된 목록 중 하나를 선택하는 방식이므로 카테고리 이름 충돌을 방지합니다.

향후 CRUD 기능을 확장할 경우에는 프롬프트마다 고유 ID를 부여하여 제목이 같더라도 서로 다른 데이터로 관리할 수 있도록 개선할 수 있습니다.

## 함수 구조

기능별로 함수를 분리하여 프로그램을 구성했습니다.

주요 함수의 역할은 다음과 같습니다.

| 함수 | 역할 |
|---|---|
| `show_menu()` | 프로그램 메뉴 출력 및 사용자 선택 |
| `add_prompt()` | 새로운 프롬프트 추가 |
| `show_list()` | 전체 프롬프트 목록 출력 |
| `show_category()` | 카테고리별 프롬프트 조회 |
| `search_prompt()` | 제목 및 내용 검색 |
| `show_detail()` | 프롬프트 상세 정보 출력 |
| `toggle_favorite()` | 즐겨찾기 추가 및 해제 |
| `show_favorites()` | 즐겨찾기 목록 출력 |

기능별로 함수를 분리하여 코드의 가독성을 높이고 각 기능을 독립적으로 수정할 수 있도록 구성했습니다.

## Git 관리

프로젝트 개발 과정에서 Git과 GitHub를 사용하여 코드의 변경 이력을 관리했습니다.

기능별로 작업 내용을 나누어 커밋했습니다.

### 주요 커밋 예시

```text
프로젝트 초기 설정
프로그램 실행 구조 추가
메뉴 기능 구현
프롬프트 목록 기능 구현
프롬프트 추가 기능 구현
카테고리별 조회 기능 구현
프롬프트 검색 기능 구현
즐겨찾기 기능 구현
프롬프트 목록 즐겨찾기 표시 개선
잘못된 메뉴 입력 처리 개선
README 프로젝트 설명 작성
```

총 10개 이상의 의미 있는 커밋을 작성하여 기능별 변경 이력을 관리했습니다.

## Git 명령어

프로젝트에서 다음 Git 명령어를 사용했습니다.

```bash
git init
git add
git commit
git push
git pull
git clone
git checkout
git merge
```

### 주요 명령어 설명

- `git init` : 로컬 Git 저장소를 생성합니다.
- `git add` : 변경된 파일을 커밋할 대상으로 등록합니다.
- `git commit` : 변경 내용을 Git에 기록합니다.
- `git push` : 로컬 커밋을 GitHub 원격 저장소에 업로드합니다.
- `git pull` : 원격 저장소의 변경 내용을 가져옵니다.
- `git clone` : 원격 GitHub 저장소를 로컬 컴퓨터에 복사합니다.
- `git checkout` : 다른 브랜치로 이동합니다.
- `git merge` : 다른 브랜치의 작업 내용을 현재 브랜치에 병합합니다.

## 브랜치 전략

기본 브랜치는 `main`으로 사용했습니다.

기능을 독립적으로 개발해야 하는 경우 `feature/기능명` 형태의 브랜치를 생성합니다.

이번 프로젝트에서는 프롬프트 목록 기능 개선을 위해 다음 브랜치를 사용했습니다.

```text
feature/list-improvement
```

기능 개발이 완료된 후 `main` 브랜치로 이동하여 merge했습니다.

이렇게 기능별로 브랜치를 분리하면 개발 중인 기능이 main 브랜치에 바로 영향을 주는 것을 줄이고, 기능별 변경 이력을 확인하기 쉽다는 장점이 있습니다.
